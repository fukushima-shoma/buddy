# 自然な会話に近づけるためのRealtime移行

目的は、子どもが待ち時間や機械的な応答を意識せずBuddyと会話できること。
API移行だけで達成したとは判断せず、待ち時間、途中で話しかけた時の反応、
直前の話題の引き継ぎ、声の聞きやすさを実会話で確認する。

## 初期実装（2026-09-13）

通常会話は`gpt-realtime-2.1`に音声を直接送り、返答音声を届いた順に再生する。
録音中から送信するため、録音完了後のファイル送信待ちを減らす。
返答テキスト生成と別の音声合成APIを順に呼ぶ処理を通常会話から省いた。
声は既存の`coral`、速度0.95、一人称「ぼく」、車の友だちの設定を維持する。

発話終了判定はRealtimeの`semantic_vad`、`eagerness=medium`を使う。
`--semantic-eagerness low`で従来設定へ戻せる。途中の言いよどみに対する実際の精度は
実会話で比較する必要がある。ローカル側の3秒watchdogは維持する。
無音の長さだけでなく発話の内容に基づいて、言いよどみでは続きを待つ。
録音の上限は発話開始から20秒。通信が使えない場合はローカルVADの無音1.4秒へ戻る。
Realtimeの自動応答は無効にし、
文字起こしを待って停止・プロフィール・記憶・遊び・短い定型応答を先に処理する。
そのため文字起こしの待ち時間は残る。常時双方向の会話はまだ導入していない。
再生中の声による割り込みとローカル停止認識は既存の仕組みを使う。
割り込みでは接続も閉じ、未再生の返答を次の会話へ持ち越さない。

共有体験と誕生日の永続保存は既存の端末内データを使う。関連する共有体験だけを
通常返答の参考に渡す。プロフィールや記憶の操作は返答用の会話文脈から削除する。
これらの発話音声も文字起こしのためAPIへ送信される。
セッションは待機への復帰時にリセットし、最大30往復で接続・文脈を更新する。

接続・入力と返答の受信停止は各10秒が上限。音声が届いている間は、長い物語を
再生できるよう受信の待ち時間を更新する。音声長の上限は通常30秒、物語90秒。
ただし手動commitで空バッファエラーが来てcommit確認がない場合だけ、
`--empty-commit-grace 1.0`の猶予で終了し、一度だけ代替経路へ進む。
猶予内にcommit確認が届けば元の10秒上限で文字起こしを待つ。
期限切れは`failure=empty-commit-timeout`として記録する。
`event-times`には入力開始からmanual-commit/empty-commit/committed/transcribedまでの
秒数を記録し、音声や認識内容は含めない。
返答全体にも音声長の上限＋10秒の処理上限がある。通信失敗後は初回3秒、
失敗が続く場合は最大30秒接続を控え、従来の文字起こし→Luna→音声合成へ戻る。
接続・入力失敗が起きた発話では同じ音声の再送とRealtime返答の再試行を省き、
完了した通常会話を復帰時に戻す。返答音声がすでに出た場合は二重に
返答しない。ローカル定型応答は従来の音声キャッシュを使う。

## 言いよどみと物語への対応（2026-09-13）

実会話で「速くなったが、途中の間で発話が切れる」「物語も短すぎる」との報告があった。
従来の無音0.4秒と最大5秒の録音から、上記の意味による終了判定と最大20秒へ変更した。
無音1.4秒は通信失敗時だけの判定で、通常時に必ず1.4秒待つ設定ではない。
意味の終了判定が未完のままでも、連続3秒の低音量で録音を終える待ちすぎ防止を追加。
発話が再開した場合はこの計測をリセットする。設定は`--semantic-silence-duration`。
意味の判定も誤る可能性があるため、子どもの言いよどみでの聞き比べは必要。

通常会話は短文を維持する。明示的な物語の依頼では1文制限を外し、180〜260文字・
6〜10文を目安に、始まり・出来事・安心できる結末まで語る。
直前が物語なら「続き」「もっと長く」「それから？」も物語として扱い、
普通の話題へ戻ったら短い返答へ戻す。クイズ中の物語の依頼はクイズを終了して扱う。
Realtimeの出力上限は通常512、物語4096トークン。従来方式へのフォールバックも
物語のときは1024トークンに増やす。

合成入力からの実API試験では、物語210文字・音声39.074秒が最後まで生成され、
最初の音声は0.972秒だった。実機再生は行っていない。
1.2秒の間を挟んだ合成発話では、間を越えて後半まで入力が保持されることを確認した。
ただし文字起こしで「くるま」の表記誤りがあり、認識精度まで改善したとは判断しない。

## 確認と比較

直近の会話だけを待ち時間・噛み合いの兆候・物語の観点で振り返る場合は
[セッション評価](session-evaluation.md)を使う。

実機のマイク・スピーカーを開かず、合成テキストからAPI出力を確認できる。
`OPENAI_API_KEY`を環境変数に設定した上で実行する。

```bash
.venv/bin/python -m robot.realtime_cli \
  --text 'こんにちは、お話ししよう' --output /tmp/buddy-realtime-check.wav
```

2026-09-13の実API試験では、テキスト入力の最初の音声が0.865秒。
生成済み音声を再入力した試験は文字起こし0.819秒、返答の最初の音声0.764秒。
録音終了判定・実機再生・周囲の雑音を含まない各1回の結果であり、実会話の改善値ではない。

同じ生成済み音声を各方式に3回入力した追加試験では、入力開始から最初の音声データまでの
中央値が従来方式3.005秒、Realtime1.678秒（約44%短縮）だった。
従来方式は4.666 / 2.850 / 3.005秒、Realtimeは1.855 / 1.659 / 1.678秒。
子ども向け指示、文字起こしモデル、声、速度は同じ設定とし、音声キャッシュと会話履歴は
毎回リセットした。Realtime接続は計測前に確立し、録音中から送る実装の送信重複は
再現せず、WAV入力から測った。両方式とも機器の録音・再生は行っていない。
試験数が少ないため、実会話の速度・音質・割り込みの改善を保証する結果ではない。

会話後、期間を指定してログを集計する。集計結果に会話本文は含めない。

```bash
journalctl -u buddy-conversation.service --since '2026-09-13 00:00:00' -o cat \
  | .venv/bin/python -m robot.conversation_metrics_cli
```

`recording-to-playback:realtime`の中央値とp90を従来の`pipeline`と比較する。
この値は録音完了から再生プロセスへの最初の音声書き込みまでで、
発話終了判定の待ち時間やスピーカーの内部バッファは含まない。
`estimated-speech-end-to-playback:<経路>`は、同じターンの末尾低音量時間
（`silence-seconds`）を録音完了→再生開始に加えた推定待ち時間。
各ターンで加算してから集計し、別々の中央値を足すことはしない。
末尾低音量は実際の発話終了の近似なので、実発音までの遅延を測った値ではない。
両指標とも`realtime`（通常）、`pipeline`（従来方式・代替経路）、
`local`（ローカル短文）、`control`（定型操作）を分けて表示する。
`pipeline`だけでは、初めから従来方式を選んだ場合と障害後の代替を区別できない。
全時間指標に件数・平均・中央値・p90・p95・最小・最大を表示する。
p90/p95は昇順の`ceil(件数 × 分位)`番目で、少数件では最大値と一致する。
`estimated_wait_samples`の`paired`が推定可能件数、`missing_silence`が
無音時間の欠損・不正などで推定から除外した件数。欠損は0秒で補わない。
ログは時系列順に渡し、複数セッションでは開始・終了境界も残す。
ターン番号の変化・セッション境界・録音完了で対応づけをリセットする。
再生開始後に届いた無音時間は遡って対応づけない。
`transcription`、`realtime-first-audio`、フォールバック件数も確認する。
新しいログでは`realtime_inputs`にRealtime文字起こしの試行数・成功数・失敗数と
安全な原因コードを集計する。通信・タイムアウト・API・認識イベントを区別し、
会話本文、音声、サーバーのエラー本文は集計へ含めない。
短いローカル応答は`local`、停止や記憶操作などの定型返答は`control`として分ける。
旧ログの`local=true`も短いローカル応答として集計する。
`input_ends`は意味による終了・無音・録音上限の件数。`duration-limit`が続く場合は、
発話が長いか終了判定が動いていない可能性がある。
`reply_modes`で物語と通常会話を区別し、長い物語の再生時間を普段の返答と混同しない。

同じ部屋・距離で短い挨拶、自由な話題、言いよどみ、訂正、途中での話しかけ、
停止、共有体験の想起を試す。中央値だけでなく、言葉を途中で切らないことと
割り込み後に返答が続かないことを保護者の聞き比べで評価する。
従来の通常会話8件の録音完了→再生開始の平均は3.865秒だった。
今後は件数と条件を揃え、中央値・p90も記録して比較する。

## 切り替え

サービス設定は`--conversation-backend realtime --sample-rate 24000`に加えて
`--realtime-turn-detection semantic --duration 20 --silence-duration 1.4`を指定する。
手動CLIの既定は従来の`pipeline`。戻す場合はサービス設定の
`--conversation-backend realtime`を`--conversation-backend pipeline`に変更して反映する。
24kHz録音は従来の文字起こしでも利用できる。
意味による終了判定だけを戻す場合は`--realtime-turn-detection manual`に変更する。

公式仕様: [Realtime conversations](https://developers.openai.com/api/docs/guides/realtime-conversations)、
[WebSocket接続](https://developers.openai.com/api/docs/guides/voice-websockets)。
発話終了判定: [Voice activity detection](https://developers.openai.com/api/docs/guides/realtime-vad)。
