# スマホで会話状態を見る

スマホをBuddyと同じWi-Fiにつなぎ、ブラウザで
`http://BuddyのIPアドレス:8765/`を開く。アプリのインストールは不要。
対応しているネットワークでは`http://buddy.local:8765/`も使える。
IPアドレスはルーターの接続機器一覧で確認できる。

| 画面 | 意味 |
| --- | --- |
| 「バディ」と呼んでね | 呼びかけ待ち |
| 緑・話していいよ | マイクで録音中 |
| 黄・ちょっと待ってね | 接続準備・音声認識・返答生成・次の録音の準備中 |
| 青・ぼくがお話し中 | Buddyの音声を再生中 |
| お話はおしまい | 会話終了 |
| Buddyにつながらないよ | サービス停止・通信切断。自動で再接続を試みる |

音声認識が確定すると、会話状態の下に「Buddyが聞き取った言葉」を表示する。
話している途中の字幕ではなく、録音終了後の認識結果なので、聞き間違いが含まれることもある。
返答を待つ間とBuddyが話している間に表示し、次の録音開始・会話終了・通信切断で消す。
表示サーバーは直近の1発話だけをメモリに持ち、表示のために履歴をファイルへ保存しない。

専用画面を用意するまでは、スマホを子どもから見える場所に立てて使う。
画面をつけたままにするボタンは、ブラウザがWake Lockに対応し、使用を許可する場合に
動作する。通常のLAN内HTTP接続では使えないことがあるため、使えない場合は
スマホの設定で自動ロックまでの時間を延ばす。

## 起動設定

`infra/buddy-conversation.service`には次の設定を追加している。

```sh
--conversation-display \
--conversation-display-host 0.0.0.0 \
--conversation-display-port 8765
```

単独のCLIでも、通常の会話コマンドに同じオプションを追加する。
表示機能は既定で無効。有効時の既定ホストは`127.0.0.1`で、Buddy自身からだけアクセスできる。
`0.0.0.0`を指定すると同じネットワークの機器から開ける。
外部ライブラリやクラウドの表示サービスは不要。

機器を使わず動作を確認する場合:

```sh
python -m robot.conversation_loop_cli \
  --conversation-display --conversation-display-host 0.0.0.0 \
  --start-trigger manual --turns 1
```

このコマンドは既定のモック録音・再生を使う。稼働中サービスと同時に動かす場合は
`--conversation-display-port 8766`など別のポートを指定する。

## 表示と通信の制約

画面は状態と現在の認識結果を約200ms間隔で取得する。音声、記憶、APIキーは送らず、
操作APIも持たない。認識結果は表示機能へ直接渡し、ROS 2の状態イベントには含めない。
HTTP処理は別スレッドで実行し、ブラウザの通信待ちを会話処理へ持ち込まない。
ポートが使用中などで表示サーバーを起動できない場合はログに記録し、会話を継続する。
既存のROS 2の会話・反応イベントも継続して送る。

録音準備中は黄で待ち、ALSA VAD録音では最初の音声チャンクを受け取ってから緑になる。
録音終了後は文字起こしの完了を待たず黄に戻る。再生開始時は青、終了後は黄に戻り、
次の録音開始時に緑になる。表示はネットワークとブラウザの遅延を伴い、厳密な同期ではない。
通信失敗時は緑などの古い表示を残さず接続エラーに切り替える。

家庭内の信頼できるWi-Fi向け。認証・HTTPSは提供しないので、ルーターでポートを
インターネットへ公開しない。ゲストWi-Fiや端末間通信を遮断するネットワークでは開けない。

表示を追加しても、子どもの言いよどみを発話終了と判定してしまう問題は残る。
実際の子どもとの会話で表示の見やすさ、録音・再生とのずれ、Wi-Fi切断時の復帰を確認する。
スマホ実機・実音声による確認は未実施。
