# 固定音声キャッシュとTTSチャンク比較

固定フレーズを事前生成し、プロセス再起動後も同じ音声を利用する。
会話で生成した音声を自動的に永続保存する機能ではない。
CLIの既定は無効。通常のRealtime音声生成には影響しない。
2026-11-08に固定文39件を実APIで準備し、Buddyの会話サービスで有効化した。
再起動後の`fixed-speech-cache=on`・`speech-chunk-bytes=16384`と正常稼働を確認済み。
全39件を新しい生成器からAPI呼出なしで読み出せることも確認した。
実スピーカーでの試聴と応答遅延のA/B比較は未実施。

## 電源オフで確認する

対象の固定文と件数を確認する。APIキー・API通信・ファイル生成は不要。

```sh
.venv/bin/python -m robot.fixed_speech_cli --list
```

モックで準備経路を確認する。実際の読み上げ音声ではなく無音WAVを生成する。

```sh
.venv/bin/python -m robot.fixed_speech_cli --limit 2
```

出力は`captures/audio/fixed-speech-cache/mock-preview/`だけに置く。
モック音声は本物の固定キャッシュとして読み込まれない。録音・再生は行わない。

## 本物の音声を準備する

以下はAPI通信と課金を伴う。環境変数`OPENAI_API_KEY`を設定した上で実行する。
マイク・スピーカーは不要。サービス起動時には自動実行しない。

```sh
.venv/bin/python -m robot.fixed_speech_cli \
  --backend openai --voice coral --style calm --speed 0.95
```

`--limit 2`を付けると先頭2件だけ準備できる。
同じ設定で準備済みの正常な音声は再利用し、`--force`を付けると再生成する。
未完了・不正な音声は公開せず、置換に失敗しても既存の正常な音声を残す。
途中で失敗した場合は終了コード1を返し、完了済みの音声は次回再利用できる。

本物のファイルは既定ディレクトリ直下の`.speech`形式。
形式版・設定のハッシュ・音声のSHA-256・WAVを一つのファイルとして原子的に保存する。
各WAVは最大4MiB、mono/24kHz/PCM16。完成したストリーミングWAVの
長さ未確定ヘッダーも受け付ける。チェックサムは保存後の破損を検出するもので、
API側が生成を途中終了したかどうかまで判定するものではない。
実音声の内容・声質・読み切りは有効化前に確認する。

モデル・声・速度・指示・本文・形式が異なる音声は使わない。
API側の声の変化で再生成したい場合も`--force`を使う。
古い設定のファイルは自動削除しない。不要になったキャッシュは運用時に整理する。
固定文だけを対象とし、名前等を埋め込んだ文や自由会話は保存対象にしない。

## 会話で利用する

既存の会話起動引数に以下を追加する。

```text
--fixed-speech-cache captures/audio/fixed-speech-cache
```

準備時と会話時の`--speech-model`、`--speech-voice`、`--speech-style`、
`--speech-speed`を一致させる。キャッシュ指定はOpenAI TTSでのみ有効。
有効なファイルがあればTTS APIを呼ばず、既存の再生・割り込み処理へ渡す。
欠損・破損・設定不一致・読取不可なら通常のTTSに戻る。
APIキーの設定等、通常生成への復帰に必要な設定は引き続き必要。
会話中はこのディレクトリに書き込まない。
移動・停止の実行と確認音声の順序は変更していない。

キャッシュを無効に戻すには起動引数を外す。
サービスの起動引数を変更する場合は別途サービスへの反映が必要。
準備済みの音声を`--force`で更新した場合、稼働中のメモリキャッシュには
以前の音声が残るため、再起動後に更新された音声を利用する。

## チャンクサイズを比較する

会話CLIに`--speech-chunk-bytes 2048`または`4096`を指定する。
既定は`16384`。許可される値はこの3種類だけ。
対象は従来方式/ローカル返答のTTS受信で、Realtimeの音声チャンクは変更しない。

単独生成CLIでは`--chunk-bytes`を指定する。
OpenAI生成時は受信したチャンクを順にファイルへ保存し、全体が完成してから終了する。
このCLIはデバイスの再生開始遅延を測るものではない。

```sh
.venv/bin/python -m robot.speech_cli 'こんにちは。ぼくはBuddyだよ。' \
  --backend openai --chunk-bytes 4096 --output captures/audio/chunk-test.wav
```

会話ログには本文を含まない次の設定イベントを追加した。

```text
turn=1 speech-output chunk-bytes=4096 cache-source=none
```

`cache-source`は`none`（今回API生成）、`fixed`（準備済み音声）、
`memory`（プロセス内再利用）。モックは`none`・`chunk-bytes=0`と記録する。
既存の`timing=synthesis-first-audio`等の計測行は維持する。
チャンク比較ではキャッシュを無効にし、各試行で新しい生成器を使って
メモリキャッシュも除外する。キャッシュ命中時は保存済み音声を一括で返すため、
その試行をチャンクの比較には混ぜない。

比較の条件・回数・採用基準は[取り込み計画](voice-latency-adoption-plan.md)を参照。
2KiB/4KiBが速いことや音切れしないことはまだ確認していない。

## 実装と検証範囲

`robot/fixed_speech.py`が固定文の登録と保存/読込、`robot/fixed_speech_cli.py`が
準備コマンド。`robot/speech.py`、`robot/speech_cli.py`、
`robot/conversation_loop_cli.py`で利用とチャンク設定を接続する。
聞き返し定数は`robot/conversation_intents.py`へ移して共用した。

モックで、準備音声の再利用・API呼出省略・設定不一致・未登録文の除外・破損・
読取失敗・原子的保存の失敗・モックとの分離・中断/失敗時のキャッシュ除外を検証する。
実API生成とサービスへの有効化は2026-11-08に完了。
実音声の品質と実発音までの遅延は未検証。

実装時の結果: 関連テスト118件成功。全体テストは444件成功、画面表示8件が
サンドボックスのローカルソケット制限で実行できず、該当ファイル12件を
ループバック通信の許可下で再実行して全件成功。合計452件の成功を確認した。
変更差分と空白チェックも確認済み。固定フレーズは39種類。

公式の[音声合成ガイド](https://developers.openai.com/api/docs/guides/text-to-speech)では、
現行の`gpt-4o-mini-tts`の提供終了予定は2027-01-06と案内されている。
今回は既存APIを維持した変更で、モデル移行は別課題として扱う。
