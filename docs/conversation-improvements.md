# 子どもとの実会話からの改善項目

2026-09-12、保護者からの実利用フィードバックを記録する。
以下は改善計画と進捗。優先順は応答時間の計測・短縮、会話の変化、表情画面の試作を提案する。

## 1. 話し終わってからのレスポンスが遅い

現状の会話ループは録音、文字起こし、返答生成、音声合成、再生を順に行う。
発話終了判定の無音時間は既定で0.8秒。実際に使用した設定と各処理の所要時間は未確認であり、
どの段階が主因かはまだ断定しない。

- [x] 発話終了から返答音声の再生開始までと、終了判定・文字起こし・返答生成・音声合成の所要時間を計測する。計測ログに会話本文や音声を追加保存しない。
- [x] 無音待ちの短縮、定型返答の音声再利用、音声合成の逐次再生、頻出する短い発話のローカル応答を実装する。
- [ ] 待っている間に「聞き取った・考えている」が伝わる表示を出す。毎回同じ相づちを挟んで会話を長くしない。

確認方法: 同じ条件で短い発話と途中に間のある発話を試し、変更前後の待ち時間の中央値と
遅いケースを比較する。短縮のために子どもの言いよどみや発話の途中を切らないことも確認する。
数値目標は初回計測後に決める。

## 2. 話が単調すぎる

現状の子ども向け指示は原則1文・最大2文、質問は1つまで、分かりやすい二択を重視する。
これが単調さに影響している可能性はあるが、実会話での原因は未確認。
会話文脈の引き継ぎは設定によって異なり、ローカルの会話保存だけでは返答に文脈は引き継がれない。

- [ ] 実利用時の会話モードと文脈の引き継ぎ設定を確認する。
- [x] 短く分かりやすい返答を保ちつつ、共感、面白い発見、ごっこ遊び、短いお話など返し方に変化を付ける。毎回質問で終わらせない。
- [ ] 子どもが出した話題を次のやり取りで拾い、同じ質問・褒め言葉・二択の連続を減らす。
- [ ] 「もう一回」「ちがう」「別の遊び」に応じて、繰り返し・訂正・話題変更を自然に扱う。

確認方法: 架空の会話例で複数ターンを比較し、直前の発言を拾うこと、返し方に変化があること、
質問攻めにならないことを確認する。最終的な楽しさや声の抑揚は保護者の聞き比べで評価する。

## 3. 表情モニターが欲しい

現状は待機・聞く・考える・話すなどの状態イベントと、リアクションに応じた文字の顔表示がある。
これを基盤に、専用画面でBuddyの状態と表情が伝わるようにする。

- [ ] まず開発用画面で、目と口を使う顔表示を試作する。
- [ ] 待機、聞いている、考えている、話している、聞き取れなかった状態を見分けられるようにする。
- [ ] まばたきや発話中の口の動きを加え、警告時は既存の優先度制御を尊重する。
- [ ] 画面表示が音声処理を待たせないようにし、表示が故障しても会話と安全停止を妨げないことを確認する。
- [ ] 試作を見てから画面サイズ、接続方式、取り付け場所、電源容量を決める。

確認方法: モックの状態イベントで表示の切り替えと警告の優先を検証し、実機導入後に
子どもの目線からの見やすさ、発熱、配線・固定、電力の余裕を確認する。画面機種と実機動作は未確認。

関連: [Phase3: 音声で会話する](phase3.md)、[Phase4: ROS 2](phase4.md)。

## 2026-09-12 実装の進捗

- Buddyを「車の友だち」とし、探検を控えめにしたキャラクター設定を独立して定義。
- 通常会話と子ども向け会話で同じ一人称、好み、性格、身体上の制約を共有。
- セッション内で作った名前やごっこ遊びの設定を自然に拾う指示を追加。
- 明示された短い共有体験を、削除されるまで端末内へ永続保存する機能を追加。
- 子どもの誕生日を、生年を含まない月日だけのプロフィールとして保存可能にした。
- 同じ返答の音声を容量制限付きのメモリ内キャッシュで再利用する処理を追加。
- 文字起こし・返答生成・音声合成と、録音完了から再生呼び出しまでの計測ログを追加。
  発話終了から録音完了までの計測は未対応。
- 質問・二択の連続を避け、話題に合う遊びや発見を返すよう会話指示を調整。
- モデル返答は原則1文・20〜25文字を目安とし、出力トークン上限と低い冗長度を設定。
- 挨拶、感謝、訂正、「わからない」、遊びの切り替え、成功、楽しさの短い完全一致発話は、返答APIを呼ばず端末内で応答。同じ意図でも複数候補を循環させる。
- 落ち着いた声を保ちながら、発見や遊びでは少し弾む抑揚を付けるよう音声指示を調整。
- リポジトリのサービス設定では文脈引き継ぎとローカル短文応答が有効。
- 表情モニターは未着手。実音声での速度・会話品質の比較も今後実施する。
