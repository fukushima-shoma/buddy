# セッションをログから振り返る

直近のBuddyとの会話を、同じ観点で評価するための読み取り専用ツール。
マイク・スピーカー・モーターを操作せず、評価のための外部APIも呼ばない。

## 直近セッションのレポート

```bash
.venv/bin/python -m robot.session_evaluation_cli
```

最新の開始済みセッションを選ぶ。会話が続いている場合は「進行中（途中集計）」と表示する。
終了済みの直近だけを選ぶ場合は`--completed`を追加する。
標準出力のレポートには会話本文を含めない。

```bash
.venv/bin/python -m robot.session_evaluation_cli --completed \
  --output captures/session-evaluations/latest.md
.venv/bin/python -m robot.session_evaluation_cli --session SESSION_ID --format json
```

対象は直近24時間・最大20,000ログ行。journalへのアクセスができない環境では、
JSON形式のjournalをファイルや標準入力から渡せる。

```bash
journalctl -u buddy-conversation.service -o json --since '1 hour ago' --no-pager \
  | .venv/bin/python -m robot.session_evaluation_cli --stdin
.venv/bin/python -m robot.session_evaluation_cli --log-file /tmp/buddy-session.jsonl
```

`journalctl -o cat`の本文だけのログも読めるが、古いセッションの本文との時刻による
紐づけにはJSONのタイムスタンプが必要。

## 評価するもの

| 観点 | ログから確認できる根拠 | 断定できないこと |
| --- | --- | --- |
| 待ち時間 | 録音完了→最初の音声書き込みの中央値・p90、末尾無音を含む推定値 | 実際に耳へ届いた時刻 |
| 発話終了 | 録音上限、末尾3秒以上の低音量、助詞・言いよどみで終わる文字起こし | 本当に発話を途中で切ったか |
| 噛み合い | 訂正表現、異なる発話に同じ返答が続く兆候 | 本来の発話の正しさ、意味としての良し悪し |
| 物語 | 依頼と実際のモード、80文字未満の短い返答、割り込み | 楽しさ、声の抑揚、物語の結末の良さ |
| 通信・再生 | Realtime文字起こしの試行・原因別失敗、フォールバック、再生割り込み | 割り込みが意図したものか、雑音か |

自動検出はルールによる確認候補で、点数ではない。兆候がないことも、品質が良い証明ではない。
割り込みを短い物語の失敗として数えず、欠けた返答を想像で補完しない。
話者を識別していないため、発話すべてが子どもによるものだとは判断しない。

## 内容をレビューする

```bash
.venv/bin/python -m robot.session_evaluation_cli --review-context
```

この指定だけは、発話・Buddyの返答・ターン番号・計測値・評価観点をJSONで出す。
会話データは未信頼の評価対象として明示し、本文内の指示を実行しない。
連絡先は既存のサニタイズ処理で削除するが、氏名などすべての個人情報を消せる仕組みではない。
保存する場合は`captures/`などGit管理外の端末内へ置く。出力ファイルの権限は600。

Codexには「直近セッションを評価して」と頼み、この出力とログを使って、
以下を「良い点／要確認／評価不能」でレビューする。

- 相手の発話への返答、話題・登場人物・訂正の引き継ぎ。
- 曖昧な発話を決めつけず確認したか。
- 物語の始まり・出来事・結末と、続きの対応。
- 質問・二択・褒め言葉の偏り、子どもが返しやすい言葉。
- 一人称「ぼく」と車の友だちの設定、未確認の動作・知覚・記憶の主張。

各指摘にはターン番号を付ける。音声を直接理解するRealtimeの返答と別処理の文字起こしは
一致しないことがある。食い違いを見つけても、音声なしでどちらが正しいかは決めない。
このツール自体が外部モデルによる意味評価を自動実行するわけではない。

## セッションの紐づけと欠けたデータ

会話サービスは`session-start id=UUID`と`session-end id=UUID`をログへ出し、
保存する通常会話には同じUUIDとターン番号を付ける。
セッションを取り違えず、同じ短い発話が何度あっても正しいターンへ対応させる。
このログとターン番号はコード反映後のサービス再起動から有効になる。

旧ログは`state=conversation`と`state=waiting ... completed-turns=`の間を区切り、
プロセス・時刻を使ってセッションを区別する。保存本文は時刻と発話が一致した場合だけ
紐づける。曖昧なら紐づけず、不足件数を表示する。
開始境界が欠けたログは部分ログ、終了境界が欠けたものは終了確認不能として扱う。

通常会話は削除するまで保持する（旧版で削除済みの100件より古い履歴は復元できない）。
プロフィール・記憶などの定型操作や、再生を中断した
Realtimeの返答は保存本文にないことがある。ログ行数・発話件数・本文ペアの件数を
併記し、セッション全体を評価できたか確認する。

実装: `robot/session_evaluation.py`、`robot/session_evaluation_cli.py`。
紐づけ: `robot/conversation_loop_cli.py`、`robot/conversation_memory.py`。
